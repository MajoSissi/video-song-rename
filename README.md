# 视频歌曲重命名

给一堆视频/音频文件「听歌识曲」，把文件名改成歌曲名。

下载来的 MV、录屏、缓存视频，文件名往往是一串时间和数字。这个工具取每段音频的中间
12 秒发给 Shazam，认出歌名后按你的命名规则改名，还能顺手把改好的文件挪进归档目录；
认不出来的打上 `0_` 前缀，方便回头人工处理。

界面长这样：左边是「任务 / 命名 / 记录 / 设置」四个页，中间是文件列表，下面是日志。
窗口没有系统那圈框架，标题栏是程序自己画的，颜色和界面一致。

---

## 快速开始

1. 把 `dist/` 整个目录拷到任意位置（U 盘也行）。
2. 双击 `video-song-rename.exe`。
3. 点「添加文件夹」选一个目录，或者直接把文件拖进窗口。
4. 点「开始」。

首次运行会在程序旁边自动建一个 `data/` 目录，配置和日志都在里面。

### 需要什么

| | |
|---|---|
| 系统 | Windows 10/11 x64。界面用系统自带的 WebView2，Win11 已经装好；Win10 若提示缺失，装一次 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/) |
| 识别核心 | `shazam-sidecar.exe`，必须和主程序放在同一个目录 |
| ffmpeg | **可选**。mp4 / mkv / mp3 / flac / wav / ogg 这些不需要它；`.wma`、部分 `.m4a` 与 `.aac` 会回退到它。放进程序同目录或加进 PATH 即可 |
| 网络 | 要能访问 `amp.shazam.com` |

### 自己构建

界面（Go）和识别核心（Rust）是两个进程，`./build.sh` 一次编完：

```bash
./build.sh              # 发布构建
./build.sh --debug      # 调试构建（保留控制台 + DevTools）
```

产物落在 `dist/`，和上面「快速开始」里那份是同一个东西，整个拷走就能跑。

不想在本地装 Go 和 Rust 的话，去 GitHub 仓库的 **Actions → 手动构建 → Run workflow**
点一下，选 release 或 debug，跑完在那一页下载 `video-song-rename-<模式>` 压缩包。
（这条路是手动触发的，不会因为推代码就自动跑。）

工具链版本、`-tags production` 为什么不能省、`dist/` 里哪些东西不该外发，
见 [DEVELOP.md](DEVELOP.md)。

## 界面

**任务** —— 主界面。添加文件、开始识别、看结果。

- 表格每行是一个文件：歌名、艺人、新文件名、状态、进度。
- 状态有：待处理 / 识别中 / 已识别 / 已改名 / 已归档 / 预览 / 未识别 / 被限流 / 失败 / 跳过。
  「已归档」是名字本来就对、只是被搬进了归档目录的那些。
- 「开始」= **接着跑**：先做还没跑过的，一个都没有时再去跑上一轮失败 / 被限流 /
  被停止的那些。所以中途按了「停止」，回头再点一次「开始」就继续，不用重新扫描。
- 「重置」= **整批重来**：队列里所有条目回到「待处理」，包括已经改名的、已归档的、
  扫描时跳过的。文件一个不少，也不动磁盘上的任何东西——只是把状态抹平，
  再点「开始」会把它们全部重新识别一遍。已经归档过的那些不会被再搬一次，
  它们留在归档目录里，最多跟着改个名。
- 「暂停」在当前文件跑完后生效，不会掐断正在跑的那一次识别。
- 点任意一行，下面的面板会显示详情和**命令预览**——那条命令就是实际会执行的，
  排错时直接复制到终端里跑。
- 勾选若干行可以「移除所选」，只移出队列，不动磁盘上的文件。「清空」则把队列整个
  丢掉（下次得重新扫文件夹）。

**命名** —— 全程序共用的一套命名规则，没有「模板库」这回事。从上到下依次是
「分隔符 → 命名 → 未识别命名 → 归档位置 → 命名预览」，改哪一格，最下面的预览
立刻跟着变。一屏就看得全，不会挂一根滚动条。

命名和归档位置在同一次保存里生效，底栏只有一颗「保存」。

**记录** —— 每次改名都记一行「原名 → 现名」。想改回去有三种：单行右边那颗
「还原」只动那一个文件；左边的勾选框勾几条、再点「还原所选」批量改回去；
右上角的「撤销全部改名」按记录倒着把整批改回去。

还原认的是**文件身份，不是文件名**：每条记录都记下了那个文件在磁盘上的唯一编号，
所以在程序外面把文件改了个名，照样能还原回去（那一行会标上「已改名」）。
只有编号也对不上时才退回按路径找；同名但其实是另一个文件的，宁可跳过也不动它。

记录多了以后，上面那行可以按关键词搜（搜的是完整路径，不只文件名）、
也可以按状态筛（全部 / 可还原 / 已还原 / 已不在）。筛选和搜索只决定「看得见哪些」，
**不会动记录本身**，也不会把你已经勾好的丢掉。

还原过的行标成「已还原」但**不会消失**——这份记录本身就是用来回查原文件名的。

**设置** —— 见下面。

## 后台运行

点标题栏的 ✕ 默认**不退出**，只是把窗口收起来，程序继续在托盘里跑。
双击托盘图标重新打开窗口，右键出菜单：

```
空闲 / 识别中 3/8 / 已暂停        ← 当前状态，灰色不可点
──────────────
显示主窗口
暂停 / 继续 / 开始处理             ← 按当前状态变
──────────────
打开数据目录
退出                               ← 真的退出走这里
```

不想让它赖在后台，就去「设置 → 窗口与后台」把「点关闭按钮时收进托盘」关掉，
之后 ✕ 就是直接退出。

**同时只能开一个。** 再点一次图标不会开出第二个，而是把已经在跑的那个窗口叫出来——
窗口收在托盘里的时候最有用，不用去任务栏里找。（两个实例会各自读一份配置、
各自跑一批改名，而改名是写磁盘的，撞上就会安静地把状态弄乱。）

## 设置

设置页按用途分了五组。

**识别**

| 项 | 默认 | 说明 |
|---|---|---|
| 取样窗口 | 12 秒 | **别调到 15 秒以上。** Shazam 对 ≥15 秒的片段一律返回空结果，所以上限锁在 14。长文件取正中间这一段。 |
| 并发数 | 3 | 同时识别几个文件。它只决定「解码和等待能重叠几份」，**不决定请求速率**——速率由下面那一项管。 |
| 失败重试次数 | 2 | 只对网络类错误重试（1/3/8 秒）。限流不走这一项，见下。解码失败和「没识别出来」不重试。 |
| 请求间隔 | 1500 毫秒 | 两次请求之间至少隔多久，默认约每分钟 40 次。**真正决定会不会被限流的是这一项**。调小可以更快，但吃到 429 的代价远大于省下的时间。 |
| 单次超时 | 20 秒 | |
| Accept-Language | `en-US` | 影响 Shazam 返回哪个语种的标题 |
| 接口国家代码 | `GB` | 拼在请求路径里 |

### 限流是怎么处理的

Shazam 那条接口没有公开配额，429 是按 **IP** 挡的：一旦被挡，这台机器上所有请求
都会被挡，重启程序、换 UA 都没用。所以程序不按「每个文件退避几秒」处理它，而是：

1. **所有请求共用一个闸门**，任意两次之间至少隔「请求间隔」。
   一个文件配了额外语种时，sidecar 内部那几次调用也按同一个间隔排开。
2. **一次 429 冻结全部 worker**，默认 60 秒，连续被挡时逐次翻倍，最多 15 分钟。
   界面上会出现「限流冷却 N 秒」的倒计时。冷却是全局的，不是某一条文件的。
3. **连续两次 429 就停掉整轮**，并把汇总原因写成一句话。
   继续跑只会把剩下的文件一条条变成红色的「失败」，而真正的原因只有一句「被限流了」。
   没轮到的文件停在「待处理」，等冷却过去点「开始」就接着跑。

**扫描范围**

| 项 | 默认 | 说明 |
|---|---|---|
| 扩展名 | 见下 | 逗号分隔，带不带点都行。默认 `.mp4 .mkv .avi .mov .flv .wmv .webm .m4v .ts .mp3 .wav .flac .m4a .aac .ogg .wma` |
| 处理子目录 | 开 | |
| 跳过已处理过的文件 | 开 | 记住处理过的文件，重新扫描时跳过，不重复打 Shazam |
| 预览模式 | 关 | 只算新名字，不改磁盘 |

**窗口与后台**

| 项 | 默认 | 说明 |
|---|---|---|
| 点关闭按钮时收进托盘 | 开 | 关掉之后 ✕ 就直接退出 |

**网络**

| 项 | 默认 | 说明 |
|---|---|---|
| 代理地址 | 空 | 空着就跟随系统的 `HTTP_PROXY` / `HTTPS_PROXY`；填 `-` 强制直连（连环境变量也不看）；其余按代理地址处理，要带协议头，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080` |
| 测试连接 | — | 按当前填的值真的问一次 Shazam，验证代理通不通。它不识别任何文件 |
| 自定义 User-Agent | 空 | 空着用内置的 App 串。填浏览器串会被 Shazam 拒绝 |

代理填错在批量跑之前是完全看不出来的——要等第一批文件全部失败才会发现。
所以改完代理先按一下「测试连接」，它用的就是输入框里当前的值，不必先保存。

**文件位置** —— 只读，显示配置、日志、识别程序、ffmpeg 各自实际用的是哪个路径。
「配置在哪」这种事不该靠猜。

### 命名规则

命名页是**槽位编辑器**，不用你手写一条模板字符串。每一格占一行，从上往下排开，
每一格都是一个下拉框，选这一格放什么；末尾的「＋ 添加」加一格，
按住任意一格可以拖着换顺序。分隔符既能全局设一个，也能每一格单独设——
每一格的补充设置就跟着它自己那一行显示，不用先点开某一格。

变量有 `歌名`、`艺人`、`专辑`、`年份`、`原文件名`，歌名和艺人都能指定语种
（英文 / 中文 / 日文 / 韩文）。

**规则里用了哪个语种，就会自动多查一次对应的语言。** 比如加了「韩文歌名」，
程序自己知道要拿韩文再问一遍 Shazam，不用你去别处配。没用到语种的规则
一次多余请求都不发。

**没识别到的位置会整格消失，连它前面的分隔符一起。** 所以
「艺人 - 英文歌名 - 中文歌名」遇到没有中文名的歌，结果是 `BTS - Spring Day.mp4`，
而不是 `BTS - Spring Day-.mp4`——不会多出一个横杠。

**重复的只写一次。** 同一段在另一个语种下取到的是同一句话时，后出现的那一格
整个消失，效果和「没识别到」一样。

最典型的就是「原版歌名 - 英文歌名」：原版歌名对一首英文歌来说本来就是英文，
两个槽位会写出同一句话。默认勾着「重复的歌名 / 艺人只保留第一个」，
上面那个例子得到 `Spring Day`；去掉勾就两段都写。

判重只在同一个变量内部做（歌名之间、艺人之间、专辑之间），歌名和艺人恰好同名时
两边都留着。比较时忽略大小写、空白和标点，所以 `Spring Day` 和 `spring  day!`
算同一句。固定文字不参与判重——写两遍是你故意的。

括号之类的装饰填进那一格的「前缀 / 后缀」：想让结果长成 `歌名 (年份)`，
就把 `(` 和 `)` 填进年份那一格。它们跟着值一起消失，年份缺失时不会剩下一个
孤零零的 `(`。

重名会自动加 ` (1)`、` (2)`，不会覆盖已有文件。

「未识别命名」也在这一页：识别不到就改成「前缀 + 原文件名 + 后缀」，
默认前缀 `0_`、后缀留空。前缀能让未识别的在文件管理器里排在一起，
后缀则不挡住文件名的开头，按习惯选一个填就行。文件名长度上限默认 120 字符，
按字符截断，不会把汉字切成半个。

### 归档位置

改好名字以后，可以顺手把文件挪走，不用再去资源管理器里手动归拢。默认**关着**，
打开后有两种落点：

**所在目录的同级目录**——文件在 `D:\Media\演唱会\xxx.mp4`，就挪到 `D:\Media\` 下
一个跟它上层同名的目录里。目录名默认取上层目录名（这里是 `演唱会`），
也能自己填一个；前后缀就加在这个名字上，比如后缀填 `_已整理`，
落点变成 `D:\Media\演唱会_已整理\`。想在归档目录里按来源分组、又不想跟原目录
混在一起时用这个。

「目录名」留空就是「跟上层同名」，但盘符根目录（`E:\`）下面没有名字可取，
那种情况必须自己填。

**指定目录**——直接填一个固定路径，相对路径按文件自己所在的目录解析。
旁边有「选择…」可以挑。

归档位置下面可以填一段示例路径「试算」一次，会立刻显示这条规则会落到哪个目录，
不用等真跑一遍才发现写错。目录不存在会自动建。

默认勾着「只移动识别成功的」——没认出来的文件留在原地，等你人工处理完再说。
去掉勾，没认出来的也会一起挪过去（`0_` 开头那批），适合确定不再回头捡的情况。

顺序是**先改名、再搬走**。搬失败（目标盘满了、目录被同名文件占了）会报「移动失败」，
但改名已经发生，所以「记录」页里照样能一键还原回去。搬完能在文件管理器里
按盘符跨卷移动，靠的是「复制 + 删源」的兜底，进度条会慢一些。

### 标题选哪个

Shazam 有时同时返回原文名和译名。默认优先级是 **英文 > 中文 > 韩文 > 日文 > 其他**，
也就是韩语歌优先用它的英文名。在配置文件里改 `title_preference` 可以调。

## 数据文件

全部在程序旁边的 `data/` 目录：

| 文件 | 内容 |
|---|---|
| `video-song-rename.json` | 设置、命名规则和归档位置 |
| `video-song-rename.log` | 运行日志 |
| `video-song-rename.undo.jsonl` | 改名记录（原名 → 现名），「还原 / 还原所选 / 撤销全部」都靠它 |
| `video-song-rename.state.json` | 已处理过的文件，用于「跳过已处理」 |

删掉 `state.json` 会让下次扫描重新识别所有文件。删掉 `undo.jsonl` 就不能再撤销了，
也查不到文件原来叫什么。删掉 `video-song-rename.json` 会把命名规则和归档位置
一起重置回默认值。

## 常见问题

**识别不出来 / 全部变成 `0_` 开头**

先看「命令预览」，把那条命令复制到终端跑一遍，输出里会写清楚是哪一步失败：

- `status: no_match` —— Shazam 听了但没匹配上。可能是纯音乐、翻唱、现场版，
  或者取样那段刚好是前奏/掌声。可以试着换个位置重新剪一段。
- `status: unsupported` —— 这个容器读不了，装 ffmpeg。
- `status: rate_limited` —— 被限流了。**等几分钟**再跑，别连着点开始；
  实在要跑就把「请求间隔」调到 2500 毫秒以上。队列里被挡的那些是橙色的
  「被限流」，用「重试失败项」就能单独再跑一遍，不用重扫。
- `status: network` —— 网络或代理问题。

**连不上 / 一直报网络错误**

先去「设置 → 网络」按一下「测试连接」。它会用输入框里当前的值真的问一次 Shazam，
几秒内就能告诉你是代理没通还是别的问题，不用等一整批文件跑完。

两个常见情况：

- **没配代理，但公司/系统装了。** 程序默认会读系统的 `HTTP_PROXY` / `HTTPS_PROXY`
  环境变量。想确认现在到底走没走代理，看「文件位置」那页旁边的日志，
  或者跑一次 `shazam-sidecar.exe --env`——它会列出所有生效的代理变量。
- **配了代理但还是不通。** 检查地址有没有带协议头（`http://` / `socks5://`）。
  只写 `127.0.0.1:7890` 会被直接拒绝，并明确告诉你是缺了协议头。
  报错里会带上最内层的原因（比如「由于目标计算机积极拒绝，无法连接」），
  一般看一眼就知道是端口没开还是地址写错了。

想临时绕开系统代理直连，把代理地址填成 `-`。注意**留空不等于直连**——
留空是「跟随环境变量」。

**「开始」点了没反应**

分两种：

- 队列里全是「已识别 / 已改名 / 跳过」——那说明这一批已经跑完了，「开始」没东西可做。
  想全部再跑一遍，点「重置」，所有条目回到「待处理」，再点「开始」。
- 队列里挂着一排灰色的「已停止」——那是上一轮你按了「停止」。现在点「开始」会接着跑
  这些，或者点「重置」把它们和已完成的一起清回「待处理」。

**改错了想恢复**

去「记录」页。只想救其中几个，就点那一行右边的「还原」；
一次要救好几个，就勾上那几行的复选框，再点右上角的「还原所选」——
按钮上会写出会动几个文件，所以按下去之前一定知道结果；
想整批退回去，就点「撤销全部改名」——它按记录倒着改回去，所以链式改名也能正确还原。

记录多了不好找，可以用上面那行搜索和筛选：搜索匹配完整路径（记得住文件夹、记不住
当时被改成什么名字的情况更多），筛选按「可还原 / 已还原 / 已不在」分。两者都只影响
**看得见哪些**，不改记录、也不动勾选。

「还原所选」只会动**此刻屏幕上勾着的那几行**：如果搜索把其中几条藏起来了，
按钮上的数字会跟着变小，按下去也只动剩下那些——不会去改你看不见的文件。

已经还原过的行会标成「已还原」，再点也不会重复动文件。文件被挪走或删掉的标成「已不在」，
这两种行的勾选框是灰的，勾不了（勾了也只会得到一句「跳过」）。
原名被别的文件占了的会跳过并在日志里说明原因——把占位的文件挪开，那颗按钮还在，可以再点一次。

在程序外面把文件改过名、挪过位置的，记录页那一行会标上「已改名」，右边显示的是它**此刻**
在哪；还原照样找得到它（按文件身份认，不认名字）。如果那个位置上现在蹲着的是**另一个**
文件，还原会跳过而不是把它改掉。

**关了窗口，程序好像还在跑**

是的，这是默认行为——点 ✕ 只是收进托盘。去托盘图标上右键 → 退出，
或者到「设置 → 窗口与后台」把这一项关掉。第一次收起来时会有个气泡提示。

**托盘图标不见了**

任务栏设置里可能把图标折叠进了「隐藏的图标」小三角。另外资源管理器（explorer.exe）
重启后程序会自动把图标加回去，不用管。

**界面上没有控制台输出**

发布构建是 `-H windowsgui`，本来就没有控制台。日志在 `data/video-song-rename.log`。
需要看实时输出就用 `./build.sh --debug` 构建。

## 和原来那个 Python 脚本的区别

原来的 `video_song_rename.py` 还在仓库里，留作参考。相比它，这一版修掉了：

- **取样窗口从 22 秒改成 12 秒。** 22 秒的窗口 Shazam 一律返回空结果，等于一直识别不出来。
- **不再整轨解码进内存。** 原脚本用 pydub 把整个音轨读进内存再切片，两小时的视频能吃掉 1 GB 以上。
- **「韩文优先」不再是空话。** 原脚本定义了韩文判断函数却从没调用过。
- **重跑不再重复烧网络。** 原脚本第二次运行会把所有文件重新识别一遍。
- **网络失败会重试**，并且区分「限流」「超时」「没识别出来」，不再一律打成 `0_`。
- **标题过长会截断**，不会因为超过 255 字符直接抛异常中断整批任务。
- **支持撤销**，改错了能一键还原。可以只还原其中几个（勾上再点「还原所选」），
  也能按记录整批倒着退回去。每次改名都留下「原名 → 现名」的记录，还原过的记录不删，
  随时能回查文件原来叫什么。
